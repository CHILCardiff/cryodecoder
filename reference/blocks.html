cryodecoder.blocks#

This module provides the framework for defining blocks as used in CHIL instruments, reading them from byte strings and converting interpreted values back to byte strings. More information on the blocks can be found here.

Blocks#

Blocks correspond to the Level 1, Level 2 or Level 3 data structures as defined by the 2026 CHIL instrument protocol. To ensure backwards compatability with the pre-2026 receiver packet formats, two formats of legacy block (Block_C_Cryoegg and Block_W_Wurst) are defined.

Each block class extends the Block abstract base class and is made up of a header (BlockHeader) which describes the block type and length, and a number of fields (Field) which contain the data within the block.

The cryodecoder.blocks module uses class definitions to describe the various blocks which make up the packet protocol.

Fields#

Each block definition contains a number of fields which are used to represent the binary encoding of data from the CHIL instruments. The Field objects is used to convert binary data to interpreted values (i.e. byte array to 16-bit signed integer), and vice versa (16-bit signed integer to byte array).

class cryodecoder.blocks.Block_A_LSM303(**kwargs)#

Stores magnetometer and accelerometer data from the LSM303AGR sensor used in CHIL instrumentation. More details on the LSM303 block format are available here.

Magnetometer data are signed 16-bit values which have a code range from -32,768 to 32,767 corresponding to sensor values of ±50 Gauss.

Accelerometer data are signed 16-bit values which have a code range from -32,768 to 32,767 corresponding to sensor values of ±2g (19.61 m/s2).

Example:

Converting magnetometer data to physical values:

# Load an LSM303 dataset
block = Block_A_LSM303(...)

# Convert the magnetometer sensor to its physical value in Gauss
mag_x_gauss = 50 * block.mag_x.value / 32768
Example:

Converting accelerometer data to physical values:

# Load an LSM303 dataset
block = Block_A_LSM303(...)

# Convert the acceleration sensor to its physical value in g
acc_x_gauss = 2 * block.acc_x.value / 32768

Note

Parameters:

  • mag_x (SignedIntField) – x-axis component of the magnetometer sensor.

  • mag_y (SignedIntField) – y-axis component of the magnetometer sensor.

  • mag_z (SignedIntField) – z-axis component of the magnetometer sensor.

  • acc_x (SignedIntField) – x-axis component of the accelerometer sensor.

  • acc_y (SignedIntField) – y-axis component of the accelerometer sensor.

  • acc_z (SignedIntField) – z-axis component of the accelerometer sensor.

class cryodecoder.blocks.Block_C_CHIL(**kwargs)#

Stores instrument battery voltage, packet metadata, temperature and conductivity measurements. The origin of the temperature measurement can with the instrument type but is typically a TMP117 sensor. More details on the CHIL block format are available here.

Example:

Get measured temperature value from the TMP117 sensor.

# Load a CHIL sensor dataset
block = Block_C_CHIL(...)

# Convert the raw temperature value to degrees celsius.
temp_raw_to_degC = block.temperature_tmp117.value / 128.0

# or use the built in .convertedValue to do the same
assert temp_raw_to_degC == block.temperature_tmp117.convertedValue
Parameters:

  • sequence_number (UnsignedIntField) – Sequence number of the transmitted packet increments by one after each transmission from 0 to 255 and then resets.

  • voltage_battery (UnsignedIntField) – Battery voltage of the instrument in millivolts (mV).

  • conductivity (UnsignedIntField) – Uncalibrated conductivity sensor measurement in millivolts (mV).

  • temperature_tmp117 (TemperatureTMP117Field) – Raw temperature value from the TMP117 temperature sensor.

class cryodecoder.blocks.Block_E_Environmental(**kwargs)#

Stores the environmental data (temperature, pressure, relative humidity) from the receiver. More details on the environmental block format are available here.

All dataloggers contain the MS5607 pressure and temperature sensor. There is the option to install an external SHT30 temperature and relative humidity sensor.

Example:

Get measured temperature and pressure values from the MS5607.

# Load a receiver environmental sensor dataset
block = Block_E_Environmental(...)

# Get the air temperature in degrees celsius.
temperature = block.temperature_ms5607.value

# Get the air pressure in bar.
temperature = block.pressure_ms5607.value
Example:

Get measured temperature and relative humdidity from the SHT30.

# Load a receiver environmental sensor dataset
block = Block_E_Environmental(...)

# Get the air temperature in degrees celsius.
temperature = block.temperature_sht30.convertedValue

# Get the relative humditiy in percent
# ...requires temperature from SHT30...
rel_humidity = block.humidity_sht30.convertedValue(
    block.temperature_sht30.value
)
Parameters:

  • pressure_ms5607 (IEEE754Float) – Surface air pressure recorded by the datalogger in bar.

  • temperature_ms5607 (IEEE754Float) – Internal air temperature of the datalogger in degrees celsius.

  • temperature_sht30 (TemperatureSHT30Field) – (Optional) External air temperature recorded by the datalogger using an SHT30 sensor.

  • humidity_sht30 (RelativeHumiditySHT30Field) – (Optional) External relative humidity recorded by the datalogger using an SHT30 sensor.

class cryodecoder.blocks.Block_K_Keller(**kwargs)#

Stores the temperature and pressure data from a Keller `7LD`_ or `7LHPD`_ pressure sensor. More details on the Keller block format are available here.

Warning

If the pressure_min or pressure_max are invalid, it can cause the pressure.convertedValue field to be incorrectly converted. If values from the pressure sensor do not look valid, make sure to check pressure.value.

Example:

Read the temperature and pressure from a Keller sensor

# Read a Block_K_Keller block
block = Block_K_Keller(...)

# Get the temperature value in celsius
temperature_degC = block.temperature.convertedValue

# Get the pressure value in bar
pressure_bar = block.pressure.convertedValue
Example:

Convert raw temperature and pressure values from a Keller sensor, if the minimum and maximum pressure are known

# Read a Block_K_Keller block
block = Block_K_Keller(...)

# Get the temperature value in celsius
temperature_degC = (block.temperature.value >> 4) - 24 ) * 0.05 - 50.0

# Set the known minimum and maximum pressure values assuming it
# is a seal gauge sensor (zero at 1.0 bar absolute).
p_min = 0.0  # minimum pressure
p_max = 30.0 # maximum pressure

# Get the pressure value in bar
pressure_bar = (block.pressure.value - 16384) x (p_max - p_min) / 32768
Parameters:

  • pressure (PressureKellerField) – measured pressure value.

  • temperature (TemperatureKellerField) – measured temperature value.

  • date_code (UnsignedIntField)

  • pressure_min (IEEE754Float) – Minimum rated pressure value (corresponding to a raw value of 16,384)

  • pressure_max (IEEE754Float) – Maximum rated pressure value (corresponding to a raw value of 49,152).

class cryodecoder.blocks.Block_V_Voltage(**kwargs)#

Stores the receiver power system data from the voltage divider input voltage monitor and power sensing INA3221 sensor. More details on the Keller block format are available here.

Note

The input voltage divider circuit on newer dataloggers appears to have a very non-linear characteristic which requires further investigation.

Shunt resistors for the INA3321 are 0.1 Ohms, which means that the current flowing through them can be calculated from the shunt voltage divided by resistance.

The shunt voltage and bus voltage fields from the INA3221 are 13 bits long and left-shifted into a 16-bit field. To convert the raw shunt voltage value to volts, multiply by 5e-6. To convert the raw bus voltage value to volts, multiply by 1e-3.

Example:

Calculate power from solar panel.

# Read a Block_V_Voltage block
block = Block_V_Voltage(...)

# Calculate current
R_shunt = 0.1 # Ohms
current_ch1_amps = block.voltage_shunt_ch1.value * 5e-6 / R_shunt

# Calculate voltage
voltage_ch1_volts = block.voltage_bus_ch1.value * 1e-3

# Calculate power
power_ch1_watts = current_ch1_amps * voltage_ch1_volts
Parameters:

  • voltage_battery (UnsignedIntField) – raw output from the voltage divider input voltage monitor.

  • voltage_shunt_ch1 (UnsignedIntField) – shunt voltage from the solar panel (channel 1), used to calculate the current.

  • voltage_bus_ch1 (UnsignedIntField) – bus voltage from the solar panel (channel 1), used to derive total power.

  • voltage_shunt_ch2 (UnsignedIntField) – shunt voltage from the solar regulator (channel 2), used to calculate the current.

  • voltage_bus_ch2 (UnsignedIntField) – bus voltage from the solar regulator (channel 3), used to derive total power.

  • voltage_shunt_ch3 (UnsignedIntField) – shunt voltage to the datalogger (channel 3), used to calculate the current.

  • voltage_bus_ch3 (UnsignedIntField) – input voltage at the datalogger (channel 3), used to derive total power.

class cryodecoder.blocks.Block_T_Tilt(**kwargs)#

Stores data from the CTi TILT-05 accelerometer and orientation sensor. More details on the Keller block format are available here.

Accelerometer data are signed 16-bit values are return acceleration values in units of milli-g. To convert to g (m2), divide by 1,000.

Example:

Convert pitch and roll to units of degrees

# Read a Block_T_Tilt block
block = Block_T_Tilt(...)

# Convert pitch and roll to degrees
pitch_degress = block.pitch_tenth_deg.value / 10
roll_degrees  = block.roll_tenth_deg.value / 10
Parameters:

  • acc_x (SignedIntField) – x-axis component of the accelerometer sensor.

  • acc_y (SignedIntField) – y-axis component of the accelerometer sensor.

  • acc_z (SignedIntField) – z-axis component of the accelerometer sensor.

  • pitch_tenth_deg (SignedIntField) – pitch (angle) along x-axis in tenths of a degree.

  • roll_tenth_deg (SignedIntField) – roll (angle) along y-axis in tenths of a degree.

class cryodecoder.blocks.Block_M_MBusPacket(**kwargs)#

Mirrors the format of the Radiocrafts UART interface packet format, acting as a transport layer for the CHIL packet contained within Payload. More details on the Keller block format are available here.

The received signal strength (rssi) can be converted to units of RSSI by multiplying with -1 and dividing by 2.

Example:

Convert received signal strength to dBm

# Read a Block_M_MBus block
block = Block_M_MBus(...)

# Convert RSSI to dBm
rssi_dBm = -block.rssi.value / 2
Parameters:

  • channel_number (UnsignedIntField) – channel number (1 or 2) on which the packet was received.

  • c_field (UnsignedIntField) – control field in the MBus packet header.

  • m_field (UnsignedIntField) – manufacturer field in MBus packet header.

  • uid (UnsignedIntField) – unique identifier, used to identify CHIL instruments, i.e. CE240001 or CF230010.

  • version (UnsignedIntField) – version field in the MBus packet header.

  • device (UnsignedIntField) – device field in the MBus packet header.

  • ci_field (UnsignedIntField) – control information field in the MBus packet header, used to discriminate between 2023 and 2026 packet formats.

  • payload (Payload) – contents of the MBus packet.

  • rssi (UnsignedIntField) – encoded received signal strength.

class cryodecoder.blocks.Block_D_Datalogger(**kwargs)#

Stores data associated with reception of a data packet from CHIL instrument.

Warning

The timestamp field may be incorrect if the receiver does not have a valid Iridium connection and has reset since being programmed.

class cryodecoder.blocks.Block_C_Cryoegg(**kwargs)#

Represents a Cryoegg packet transmitted by a 2023 version of the CHIL datalogger.

The Block_C_Cryoegg combines properties which are distributed across Level 1, 2 and 3 blocks in the new format. It contains measured values from the environmental sensors in the receiver in addition to the reported Cryoegg data. 2023 version Cryoegg instruments do not have accelerometers installed so this information is not available.

Note

See Block_M_MBusPacket for hints on interpreting the MBus parameters:

  • c_field, m_field, uid, version, device, ci_field and rssi.

See Block_M_MBusPacketCryoegg2023 for hints on interpreting the 2023 Cryoegg parameters:

  • conductivity, pressure, temperature_keller, battery_voltage and sequence_number.

Example:

convert logger_voltage to a value in Volts

# Load a Block_C_Cryoegg
block = Block_C_Cryoegg(...)

# Convert the raw logger voltage using a first-order polynomial
# V = m * raw + c
m = 0.0187
c = - 27.713 
battery_voltage_V = m * block.logger_voltage.value + c
Parameters:

  • timestamp (UnsignedIntField) – time at which the packet was received as a Unix timestamp (seconds since 1970-01-01 00:00:00).

  • logger_pressure (IEEE754Float) – Surface air pressure recorded by the datalogger in bar.

  • logger_temperature (IEEE754Float) – Internal air temperature of the datalogger in degrees celsius.

  • logger_voltage (UnsignedIntField) – Raw value representing the battery voltage at the receiver.

  • channel_number (UnsignedIntField) – The radio channel number (1 or 2) on which the packet was received.

  • length (UnsignedIntField) – The length of the MBus packet that follows this byte.

  • c_field (UnsignedIntField) – control field in the MBus packet header.

  • m_field (UnsignedIntField) – manufacturer field in MBus packet header.

  • uid (UnsignedIntField) – unique identifier, used to identify CHIL instruments, i.e. CE240001 or CF230010.

  • version (UnsignedIntField) – version field in the MBus packet header.

  • device (UnsignedIntField) – device field in the MBus packet header.

  • ci_field (UnsignedIntField) – control information field in the MBus packet header, used to discriminate between 2023 and 2026 packet formats.

  • conductivity (UnsignedIntField) – Uncalibrated conductivity sensor measurement in millivolts (mV).

  • temperature_pt1000 (SignedIntField) – Unused value from the PT1000 temperature sensor (deprecated).
